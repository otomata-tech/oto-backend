# Capacités dont la RÉPONSE n'est pas déclarée (`Capability.Output`).
# Une capacité NEUVE ne doit jamais s'ajouter ici : déclare son Output.
# Cette liste ne peut que DÉCROÎTRE — cf. tests/test_capability_outputs.py.
#
# Ce qui reste ici n'est PLUS de la couverture publique perdue : ces capacités
# n'apparaissent pas dans /api/openapi.json (préfixe admin exclu du document, ou
# aucune face REST). Deux exceptions qui, elles, comptaient : les surfaces
# consolidées (me.project, me.doc) — un Output unique ne peut pas décrire des
# dizaines de verbes derrière un seul chemin, cf. #269.
# `me.kb` en est SORTIE : une seule `op`, réponse déclarée en entier (`KbView`).
#
# Elles ont été MESURÉES le 2026-08-11 — chaque `return` de leur handler énuméré
# (15 pour me.project, 20 pour me.doc, 7 pour resources.govern), puis les formes
# intersectées. **L'enveloppe commune à toutes leurs `op` est VIDE** : aucune clé
# n'est présente dans toutes les réponses d'une même surface. Une intersection vide
# est un résultat, pas un échec — c'est la preuve que la surface est indescriptible
# PAR UNE ENVELOPPE ; déclarer une enveloppe qui ne tient pas ferait générer des
# types FAUX chez l'intégrateur, ce qui est pire que l'absence. Ce qui bloque :
#   me.project       — `list`/`list_templates` ne rendent que {projects}. Et même en
#                      les écartant, `lint` nomme sa cible `project_id` là où les 12
#                      autres ops par-id rendent `id`.
#   me.doc           — `bulk_create` ne rend que {created, count} ; `revisions`/
#                      `backlinks` nomment `doc_id` quand la vue de page nomme `id`.
# Le dénominateur commun de ces deux blocages est le même défaut, à signaler sans
# le corriger ici (une réponse servie en prod ne se re-façonne pas pour arranger un
# schéma) : la CIBLE d'un appel est nommée `id` dans une op et `project_id`/`doc_id`
# dans sa voisine. Le jour où ces surfaces seront converties, une seule convention
# de nommage de la cible suffirait à rendre l'enveloppe non vide.
#
# ⚠️ **resources.govern EST SORTIE le 2026-09-01 (#659), et la mesure de 2026-08-11
# n'était pas fausse — elle répondait à une autre question.** L'enveloppe commune est
# bien vide ; c'est l'UNION des cinq verbes qui décrit cette surface, et elle se
# déclare sans cran technique (`capabilities/resources_contract.py`). La leçon vaut pour
# les deux qui restent : « pas d'enveloppe » ne veut pas dire « indéclarable ». Une
# union se discrimine quand les formes portent un champ qui les sépare — ici
# `resource_type`, dont les trois familles ne rendent pas les mêmes clés.
